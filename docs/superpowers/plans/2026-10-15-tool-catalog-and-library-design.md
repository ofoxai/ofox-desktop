# OFox 可选工具安装与资源库设计

状态：已确认，实施中。日期：2026-10-15。当前完成状态和验收边界见[实施记录](../../implementation-progress-2026-10-15.md)；本文仍是目标范围，不表示全部能力已交付。

本项目代码基线为 `51d2268e`；用量设计已在 `73e86371` 提交。本文补充用户新增的两项范围，与[用量分析设计](2026-10-15-usage-analytics-design.md)共同组成下一轮规划。Magpie 参考源码为 `bfaedf18`，同时参考用户提供的“安装其他 Agent”和“资源库”界面截图。

## 1. 已确认的产品决定

1. 增加更多可选工具，用户自行选择；“安装其他工具”始终默认折叠，包括首次使用和没有已安装工具时。
2. 这些工具首期不进入 OFox 绑定页面，也不因安装而签发 Key、写模型、接管路由或加入 `ofox-bound-tools`。
3. 新增顶层“资源库”，提供“指令／提示词、MCP、Skills”三个子页，参考 Magpie 的统一资源与按工具分配方式。
4. 资源分配不依赖 OFox 模型绑定。安装能力、模型绑定能力、资源能力、会话／用量能力分别声明；任何一项不推断另一项。
5. 复用既有数据、查询及适配器，但安全写入改造与新入口一起交付，不能仅将旧页面挂回新版界面。

推荐顶层导航为“工具／会话／资源库／用量”。资源库首期面向全局原生配置；项目作用域、Hooks、RTK 和远程 OAuth 代理为后续独立范围。

## 2. 基线实现与需要解决的风险

以下描述 `51d2268e` 基线。该版本的旧 `App.tsx` 已有 MCP、Skills、Prompts 页面和命令，实际主入口走 `MainApp → ConsolePage`，因此旧资源页面当时不可达。后续实现及验收状态见[实施记录](../../implementation-progress-2026-10-15.md)。

- **MCP 已有**：统一 CRUD、从工具导入、Claude／Codex／Gemini／OpenCode／Hermes 五类格式转换和启停。
- **Skills 已有**：仓库发现、市场搜索、ZIP／本机目录／已有技能导入、统一存储、链接／复制、更新、备份与恢复。
- **提示词已有**：每工具多份内容、单份启用、导入全局指令文件。
- **新版需要补**：资源库入口、共享资源身份、目标能力、受管所有权、冲突处理、逐目标状态、统一操作与恢复。

基线风险不能继承到新产品：旧提示词会整文件替换，最后停用可能清空文件；旧 MCP 先保存 DB 再写目标，删除按同名 ID；旧 Skills 可能先移除同名目标再同步。这些是 R0／R1 要解决的起点，不能当作当前实现仍沿用的行为。原子写入单个文件也不代表跨工具和数据库事务已经成立。

## 3. 可选工具安装

### 3.1 放置与展示

工具页上方保留当前 OFox 工具、模型和方案管理。在下方增加两个独立区域：

```text
当前 OFox 工具及方案管理
其他已安装工具（N）            默认折叠
安装其他工具（N）              默认折叠
```

两个区域使用独立工具 inventory，不复用绑定选择器。折叠状态只记当前会话，重新打开仍默认折叠；搜索和分类在用户展开后显示。

候选行包含名称、图标、产品类型、安装方式、平台／运行时要求、官方来源和动作。CLI agent、桌面应用、开发工具、IDE 扩展分开；CLI 的安装状态不代表同名 IDE 扩展已安装。

可执行动作按当前主机明确分为：一键安装、复制官方命令、打开官方下载安装页、当前平台不可用。只核实身份但未验证平台的项显示“平台待核实”，不能提供可执行的一键安装。

安装完成后重新探测实际程序、版本、路径和安装来源，进入“其他已安装工具”。只管理安装生命周期，不显示 OFox 模型选择、余额、Key 或绑定开关。不要求用户再经过绑定页才能看到它。

展示去重基于统一 `toolId` 和产品变体：上方为 bound IDs，“其他已安装”为已确认 inventory 减去 bound IDs，安装候选为已确认未安装且不在上方的产品。已绑定但程序缺失留在上方显示修复状态。已安装但尚未绑定的 Claude／Codex／Pi 等也可出现在其他已安装区，不自动选中绑定；检测 unknown 单独标“待检测”，不当成未安装。同产品多个可执行来源在同一行展示并选择实际管理来源，不能变成多个同名安装项。

已安装行提供打开、版本与路径、官方文档、检查更新；升级和卸载只在能够识别实际安装管理器及保留数据语义时开放。未知来源提供手动说明，不因同名 bin 猜 npm 包。自动卸载继续复用预览／保留数据／部分结果流程。

本机目录与资源库应有“暂不绑定，进入本机管理”的通路。当前无绑定会进入 onboarding，这需要增加明确入口，并作为 I1 的同批交付前置；登录失效不使本机资源消失，也不偷偷切换或恢复模型绑定。

本机模式账户区提供登录动作，不呈现依赖账户的模型／余额操作；登录恢复保留当前本机页面，额外工具仍不自动绑定。全新未登录、已登录零绑定和认证过期分别验收。

### 3.3 目录与任务模型

建议拆分 `InstallCatalogEntry`、`InstalledTool`、`BindCapabilities`、`ResourceCapabilities`：共用稳定 `toolId`，但数据来源和用途独立。

安装目录保存官方来源、产品类型、程序身份、平台／架构方法、运行时要求和核实状态；inventory 保存实际探测结果。新增额外工具不能扩大当前绑定 `TOOL_ORDER`，不能强制新增旧 `AppType`，也不使用绑定列表作为已安装名单。

复用已有安装进度、更新归属与 Node 检查。额外目录的自动任务按 `operationId` 隔离，先订阅再执行；同一个包管理器写操作串行，重复点击合并／拒绝。失败保留安装错误及重试动作，不伪造“安装成功”。

依赖缺失单独说明；工具安装不能暗中升级用户 Node／Bun／Python，或替用户进行厂商登录。复制命令是复制操作，打开目录不会运行命令。官方命令的展示不代表自动执行该 shell 字符串：自动安装使用固定白名单及结构化 recipe。

## 4. 资源库页面设计

资源库下设“指令／提示词、MCP 服务器、Skills”；子页有计数、搜索、添加／导入、刷新及备份入口。共用目标选择、预览和应用结果组件，不把每个工具做成独立资源孤岛。

目标来自已发现且具有该资源能力的工具，不限于已绑定 OFox。首期优先完整接通当前五类全局适配器；其他工具需要自己的适配和安装版验证后才显示开关，不能因安装目录收录就宣称三类资源都支持。

### 4.1 指令／提示词

首期“提示词”指供工具每次会话读取的共享 Markdown 指令，不是对话中的自动发送消息，也不是由 OFox 执行的指令。

界面参考截图：上方共享指令集，下面按工具列出目标文件、现有自有内容、所用指令集和同步状态。

- 多个命名集合，支持新建、编辑、复制、预览、导入 Markdown；每个目标全局作用域选择一套，默认不自动启用。
- 一个共享集合可以分配给多个工具；修改后对已分配目标预览差异并应用，显示成功、冲突、失败。
- 工具行显示原生目标位置、受管／自有内容及最后结果。用户内容不自动导入共享集；导入只创建草稿。
- 用户可以保留每个工具独有指令；只同步 OFox 专属 marker 中的块，块外内容逐字保留，关闭只撤回自己的块，不清空文件。
- 残缺／重复 marker、手工修改过的受管块、不可读文件均进入冲突状态。不能将解析失败当作空文件或默认内容。
- 旧 Prompt 的启用标志不证明文件所有权。旧数据只读导入，不自动接管；重复内容需预览后由用户选择保留或显式转为受管区块，不能叠加相同指令两次。

保持 BOM、换行、权限和 symlink 语义；对不可写目标说明原因。内容编辑不得嵌入与管理器冲突的 marker。项目级指令后续增加，不假设所有工具都读取项目根 `AGENTS.md`。

### 4.2 MCP

- 管理统一服务器定义：stdio 命令／参数／env 引用，或原生支持的 HTTP／SSE URL、header 引用。
- 提供添加、编辑、现有工具导入、复制模板；查看支持目标、逐工具开关、配置预览和应用结果。
- 工具各自使用原生格式和目录；不支持的 transport／字段禁用并解释，不把所有工具写成同一 JSON schema。
- 同名非受管配置保留；允许换名，或经明确预览接管选定项。更新合并 OFox 拥有的字段，保留用户新增字段和注释。
- 关闭只撤回 Applied 能证明的字段／项。用户修改过的字段保留并报告冲突，不按 ID 删除整个同名服务器。
- “检查连接／工具列表”由明确操作触发，有超时、取消和步骤说明；浏览资源库不启动 MCP 程序或自动下载包。
- OAuth 首期交给工具的原生授权流程，显示待授权／需工具内操作。无需为共享认证引入本地网关，不伪造登录成功。

env／header 默认使用可分发的环境变量引用，按工具语法转换。目标不支持引用时说明限制，不自动展开秘密成明文。OFox keyring 中的值不能假设外部 CLI 能读取。

旧 MCP 配置可能在 DB 中包含明文值。导入 DTO、列表、日志、错误和默认导出统一脱敏，覆盖 env／header、URL query 及参数中的敏感值，不能只按字段名猜安全。保留／转换旧凭据必须明确显示迁移状态，不能声称隐藏 UI 就已完成凭据迁移。

编辑回写使用“保持原值／设置新值／明确清除”三种字段操作和后端引用；名称等普通字段编辑不影响秘密。显示掩码不是配置值，省略字段不代表清除。旧完整配置 API 进入协调器时同样核对引用和版本，禁止将脱敏掩码写回密码。

### 4.3 Skills

- 复用已安装列表、仓库发现和搜索，支持 Git 仓库／ref、本机目录、ZIP、工具已有技能导入。
- 详情展示 `SKILL.md`、文件列表、来源、固定提交／hash、目标范围和状态；先导入资源库，再明确选择分发目标。
- 目标支持链接或受管复制，按实际平台选择并显示方式；Windows 链接不可用时可回退复制，结果必须反馈。
- 同名非受管目录拒绝覆盖。链接仅移除自己的链接，不删除外部源目录；复制目标用 Applied hash 核对所有权。
- 更新先检查资源库源与目标副本的本地修改。修改冲突默认跳过，可比较、另存或明确选择替换；不能只凭“已经备份”静默覆盖。
- 卸载从资源库移除与从目标撤回是两个动作，结果逐目标反馈；失败保留剩余目标记录和重试入口。备份支持恢复，不默认永久删除。
- `~/.agents/skills` 等共享目录需展示实际可见工具范围，以共享目标组呈现分配，而非伪装成完全独立工具开关。取消某工具的分配而共享目录仍供其他工具使用时显示“未单独分配，仍可从共享目录读取”，不能显示隔离意义的“已关闭”。
- 仓库／ZIP 内容先验证路径、链接、体积和 `SKILL.md`，下载不执行脚本。技能内容是用户提供资源，资源库本身不执行其说明。

市场推荐、批量更新和项目技能可后续扩展；首期不开放无法证明所有权的“删除所有工具同名技能”。

## 5. 安全同步、持久状态与兼容

### 5.1 统一写入协调

```mermaid
flowchart LR
  A[资源定义与目标选择] --> B[能力校验 / 差异预览]
  B --> C[操作记录与共享文件锁]
  C --> D[工具原生适配器 / 原子写入]
  D --> E[Applied 所有权与逐目标结果]
  E --> F[冲突处理 / 撤回 / 恢复]
```

资源状态独立于模型绑定快照。取消 OFox 模型绑定不撤销资源分配；关闭资源只撤回它自己的内容，不移除模型／effort／其他 MCP／技能。

协调器区分 desired 与 applied。保存定义不等于全部目标已写入。Applied 保存目标、受管字段／块／路径、写入前受管状态、最后指纹和结果；更新／撤回先比较当前内容，不恢复整份旧文件覆盖用户后来修改。

实际写入位置经 resolver／symlink 规范化形成物理目标组，同一文件或技能目录的多个逻辑工具合并占用和 receipt。同一受管资源最后一个分配者撤回后才移除；不同指令集或定义争用同一位置时报告冲突，不按工具顺序互相覆盖。组内仍能读取的工具在界面明确列出。

一次应用有稳定操作 ID 和 revision。使用与模型写入相同的目标文件锁，避免 MCP 与模型同时改 `config.toml` 等文件。单目标使用 `atomic_write`／`FileTxn`；多目标允许清晰的部分成功，只重试失败／冲突目标。

文件与 DB 之间使用持久操作记录：prepared→写入→核对→记录 applied。崩溃后按实际文件与指纹恢复状态，不把未完成目标标成成功；未知状态进入待核对，不盲目覆盖。旧 mutation API、deeplink、后台同步等全部进入协调器，不能保留可绕过保护的旧整文件 writer。

### 5.2 保持 v11 的持久化方案

现有 MCP／Skills 表仍保存资源定义；旧 Prompt 表作为导入来源。共享指令集、泛化目标分配、Applied 和操作日志采用已有 `settings` 表中的版本化 `library_*` JSON 键，作为正式持久数据，不放到可清理缓存。共享指令集内容由该键统一管理，不再同步保存到多个每工具 Prompt 行。

定义键、目标选择键与本机 Applied／执行日志键分开。写入通过单一协调器、revision 校验和 SQLite 事务，不通过连续无锁的 `set_setting` 调用假装原子。旧五类 enabled 标志仅为兼容投影，不再作为同步成功或所有权依据；新目标不继续加 `enabled_*` 列。

本机路径、Applied、操作日志和恢复材料不得被跨机器同步为“已应用”。资源定义备份可以携带，目标分配导入后需重新选择／核实；备份、恢复、SQL 导入和 WebDAV 显式过滤／保留机器本地键，不能仅因为放在 settings 表就继承普通设置同步行为。

恢复备份时先展示定义和旧状态，不自动按旧 receipts 写工具文件。旧数据导入幂等、默认不新增分配；保留用户已有文件。损坏或未知版本的持久状态应阻止写入并保留证据，不能重置为空后清理目标。

SQL 导入、备份恢复及 WebDAV 应用与资源写入使用同一协调屏障，不能在 apply 已 prepared 时替换定义后继续旧写入。恢复完成提升状态 epoch；旧任务仅核对实际文件，不自动续写或提交旧 revision 的 receipt。引用资源已不存在的本机 receipt 保留为待处理项，不自动删除其文件内容。

该方案无需改主 schema，但引入新的持久数据契约，必须实现完整序列化、备份／恢复和升级测试。如果后续状态规模／关系查询要求改为专表，另做正式 migration；不能新增 DDL 却不管理版本。

### 5.3 备份与凭据

资源库专用备份默认只包含可携带定义、指令和技能文件及来源信息，排除秘密值、绝对目标路径、Applied 和本机执行状态。恢复有预览、同名冲突处理和逐项结果。

现有整库备份可能包含旧 MCP 明文配置，不能把新资源库脱敏导出等同于全应用备份已安全。实施时审计所有导出／日志路径，明确本机受保护备份与可分享资源包的边界；可分享包只使用脱敏导出入口。

## 6. 界面与验收

沿用 OFox 主题 token、ListCard、MenuSelect、Dialog、Progress 和折叠组件。900px 下四个顶层导航可用；资源标签、目标状态和行操作不挤占内容。浅／深色、长路径、三语、键盘与焦点独立验收。

折叠标题为按钮，支持键盘且具有 `aria-expanded`；关闭后内部不在 Tab 序列。菜单到编辑／预览弹窗焦点正确交接，后台刷新不关闭编辑器；完成／取消后返回触发项。

必须建立的回归项：

- 额外工具安装、探测、打开和重试均不调用发 Key／绑定／模型写入，不更新绑定列表。
- 未登录、无绑定、账户失效后仍有本机管理通路；当前账号变化不影响资源所有权。
- Pi／omp、WorkBuddy／CodeBuddy、DevEco Code／CLI、Cline CLI／扩展不能误识别或升级错包。
- 当前平台不支持时无假一键安装；包管理器和依赖未知时不猜。进度不串 operation，重复操作不重复执行。
- 用户指令前后文、BOM／换行不变；marker 损坏、手动编辑、不可读文件不覆盖；停用不清空文件。
- 同名 MCP／Skill 不误删，MCP 未知字段和注释保留；模型与 MCP 同文件并发更新不丢字段。
- Skills 更新保留修改，链接移除不删除源，部分撤回失败可重试，共享目录提示实际范围。
- 双工具经自定义目录／symlink 指向同一位置时，撤回其中一个不移除另一个仍使用的内容；冲突定义不能互相覆盖，共享目录状态不宣称虚假的隔离。
- prepared／写入后／持久结果前崩溃可核对；desired 与 applied 不混同。
- 导入／恢复与 apply 并发受屏障保护，epoch 变化阻止旧写入；孤立 receipt 保留待处理，脱敏字段编辑保持／更新／清除语义正确。
- 旧导入不自动接管，重复导入不制造重复资源；恢复／WebDAV 不继承其他机器的 Applied。
- 秘密不进入普通 DTO、日志、默认 CSV／资源包；MCP 健康检查只由明确操作触发。
- 全部写入测试使用沙箱，遵守共享串行锁；原生 Windows 链接、配置格式及安装验收单独完成，Mac 类型检查不替代。

## 7. 交付顺序

新增模块与用量模块分别验收；默认一条实现线，不同时开多个 Rust 大构建。

1. **I1：安装目录独立交付**。目录／inventory 分离，默认折叠、官方来源、主机能力、手动安装入口和安装后展示；最小未登录／无绑定本机管理入口同批完成。先交付更多选择，不等待所有候选自动安装。
2. **R0：资源写入前置改造**。持久分配与 Applied、共享文件锁、preview／apply／恢复，旧写入口统一协调；安全不变量先取得失败测试。
3. **R1：资源库三页交付**。接回可复用查询与编辑，完成共享指令、五类已有全局 MCP／Skills 目标、冲突与备份，复用 I1 已交付的本机管理入口。
4. **I2：逐工具自动安装与资源适配**。按平台原生验收开启自动安装、更新及资源能力；目录候选不等于已支持。优先验证首批常用 CLI，未验收保留手动途径。
5. **U：用量分析核心阶段**。继续执行用量方案 A–D，复用稳定工具身份和能力信息；新增安装工具不自动宣称可统计。
6. **后续迭代**：项目作用域、更多目标、市场体验、用量高级分析。每次独立评审及门禁，不把它们当 I1／R1 的交付前置条件。

I1、R1、I2、U 均有可独立验收的结果。最终代码版本重新运行前端 typecheck／format／全量单测和 Rust fmt／all-targets clippy／全量测试；跨平台部分以同 SHA 原生结果验收。只 commit，不 push、不改版本、不打标签。初始设计阶段没有执行安装或写入；后续实施的破坏性验证仅限沙箱，不真卸载本机工具。
