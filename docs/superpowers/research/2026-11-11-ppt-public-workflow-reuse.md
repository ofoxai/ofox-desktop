# Public PPT workflows: what Ofox can reuse for image planning, slots and review

Date: 2026-11-11. Scope: three public repositories read at pinned commits (shallow fetch of the exact SHA into a scratch directory outside this repository; `git rev-parse HEAD` matched each SHA). Nothing was copied into Ofox, no model was called, and nothing from the closed-source `ofox-agent` was used. This note extends [the 2026-11-09 design-system research](2026-11-09-ppt-design-system-research.md) and does not repeat its resource/engine comparison.

Targets: the five open quality problems — (P1) images covering the title/subtitle, (P2) cards too tall with empty space, (P3) repeated compositions in the second half, (P4) page plan not matching the final layout/narrative, (P5) features or numbers the user never gave written as facts.

"Spec" below means skill/prompt text a model is asked to follow. "Code" means an executable check or transformation. Line ranges are at the pinned commit.

## 2. Adaptation proposals for Ofox

All additions are optional-compatible fields on the existing plan (`assistant-runtime/src/presentation-planning.mjs`, mirrored by `validate_slides` in `src-tauri/src/services/assistant/presentation.rs` L719 ff.), skill sentences in `assistant-runtime/skills/ofox-office-pptx/SKILL.md`, and lint lines in `assistant-runtime/src/python/deck.py`. The Python/OfficeCLI engine, the four-image cap and the budget snapshot stay as they are. Rules are written in Ofox's own words; no upstream text is copied.

### A. Image slot contract → P1 (image over title)

Idea from PPT Master (ratio from region, quiet zone, crop policy) and Presenton (target size bound to the slot, nearest provider size).

New fields inside `slides[].visual`, required when `kind` is `user-image` or `generated-image`, forbidden otherwise:

| Field       | Type / values                                                   | Meaning                                                                                                                      |
| ----------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `placement` | `"side"` \| `"band"` \| `"inset"` \| `"full-bleed"`             | How the picture relates to native content.                                                                                   |
| `textZone`  | `"none"` \| `"left"` \| `"right"` \| `"top"` \| `"bottom"`      | Where native text sits on top of the picture. Must be `none` for `side`/`band`/`inset`; must not be `none` for `full-bleed`. |
| `aspect`    | `"16:9"` \| `"3:2"` \| `"4:3"` \| `"1:1"` \| `"3:4"` \| `"2:3"` | Shape of the box the picture will fill.                                                                                      |
| `crop`      | `"adaptive"` \| `"no-crop"`                                     | `no-crop` for screenshots, charts, logos, anything with labels or edge content.                                              |

Checks:

1. Freeze (`checkedPlan`, around L363) rejects an image visual missing any of the four, a `full-bleed` with `textZone: "none"`, and one `assetId` used with two different `aspect`/`crop` values.
2. Host generation: today `generate_image` takes a size "only when the user states a size" (`media-tools.mjs` L133–135). For a call carrying `presentationAssetId`, the host derives the size from the frozen `aspect` by nearest-ratio choice among the model's sizes and reports `requested → delivered` when they differ. `image_guidance` (`presentation.rs` L440–464) appends, in Ofox wording: no text in the picture; and for `full-bleed`, "keep the `<textZone>` part calm and low-contrast for a native title".
3. Python `image()` (`deck.py` L1300): raise when `fit="cover"` is used on a `no-crop` asset; lint when the drawn box ratio differs from the planned `aspect` by more than 15%.
4. `_validate_layout` (`deck.py` L1350 ff.) gains a picture/text pass in the same style as the existing chart/text pass: for `side`/`band`/`inset`, any intersection of the asset picture with a text frame is reported as `image/text overlap: picture "Asset <id>" and text shape <id> intersect W × H in`. For `full-bleed`, text frames whose centre lies outside the declared `textZone` half are reported.
5. Skill review step: an overlap finding must name both shapes; "looks fine" is not an answer to a host-reported overlap.

### B. One image look per deck → whole-deck consistency

Idea from PPT Master's single deck rendering. New top-level plan field `imageStyle`: `text(300)`, one sentence naming medium, line/texture, lighting and how the style palette is used. Freeze rejects a plan with any `generated-image` and no `imageStyle`, and rejects `imageStyle` when no generated image is planned. The host prepends the same sentence to every asset's guidance, so page purposes vary while rendering does not.

### C. Rhythm and page kind → P3 (repetition) and P2 (hollow cards)

Idea from PPT Master's rhythm tags and roster check, and Presenton's "adjacent layouts differ unless necessary".

| Field                 | Type / values                                                                                                                                                                                                            | Meaning                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| `slides[].pageKind`   | one archetype id from the chosen style's `pageKinds.adapted` or `.approximate` (already returned by `get_presentation_candidates`: `cards`, `statement`, `stats`, `comparison`, `process`, `timeline`, `split-image`, …) | The composition family the page will use.                           |
| `slides[].rhythm`     | `"anchor"` \| `"dense"` \| `"breathing"`                                                                                                                                                                                 | Structural page, information page, or deliberate low-density pause. |
| `slides[].continuity` | optional `text(200)`                                                                                                                                                                                                     | Why this page deliberately repeats its neighbour's composition.     |

Checks:

1. Freeze rejects a `pageKind` outside the chosen style's lists.
2. Freeze rejects three consecutive non-anchor pages with the same `pageKind` unless each page in the run has `continuity`; and for decks of eight or more pages, rejects a second half whose non-anchor pages use fewer than three distinct `pageKind` values while the style offers three or more (again waived by `continuity`). The error names the page ids and the unused kinds.
3. `card()` (`deck.py` L700) gets the same fit lint `steps` already has at L785: when the box is more than about 0.6 in taller than its text needs, report "card: box H in, text needs N in" and tell the model to shrink the box or add content. Pages planned `breathing` are exempt.
4. Skill review step asks for the specific hollow container, not a general "too empty".

### D. Built vs planned → P4 (plan drift)

Idea from PPT Master's carrier receipt and `spec_says` / `render_delivers`, and PPTAgent's review bound to the reviewed artifact.

1. Receipt (no new plan field): the deck helper records, per slide, which page/component helpers were called and the title text. The preview result adds `planCheck: [{ slide, plannedKind, builtWith: string[], plannedClaim, title, plannedVisual, hasPicture, hasChart, hasEquation }]`. The host marks `drift: true` when the planned visual kind is absent (e.g. `native-chart` planned, no chart shape) or when `builtWith` contains no helper belonging to `plannedKind`. Drift is an issue line like the existing ones, not a hard stop.
2. Review record on delivery: `create_document` without `preview` accepts optional `review: { previewId, verdict: "pass" | "issues-remain", issues: [{ slide: int, severity: "blocker" | "major" | "minor", description: text(300), shapes?: string[] }] }`. Host checks: `previewId` must be the latest preview of this run (a review of an earlier preview is refused as stale); `verdict: "pass"` with a `blocker` or `major` issue is refused; an issue answering a host overlap finding must carry `shapes`. `issues-remain` delivers and the unresolved list is shown to the user, matching the current "state unresolved issues" rule.
3. Bounded re-review: keep the existing two previews per reply. The second preview result adds `resolved` and `new` issue lists against the first. When the second preview has new overlap/clipping findings and fewer were resolved than introduced, `nextAction` tells the model to deliver the first preview with `fromPreview` — the rollback idea, without a third round.
4. Whole-deck look: the overview image is already the deck-level view. The skill adds one deck-level question set after the per-page pass: does the claim order read as the planned story, which pages look alike, which page is the visual outlier — each answer naming slide numbers.

### E. Declared facts → P5 (invented numbers and features)

Idea from PPT Master's fact IDs and `scenario` class (spec only upstream; Ofox can make part of it executable).

New field `slides[].facts`: array (max 12) of `{ value: text(120), source: "user" | "attachment" | "web" | "computed" | "illustrative", ref?: text(200) }`. Every number, date, percentage, price and named product capability shown on the page appears here with where it came from.

Checks:

1. Freeze rejects `source: "attachment"` or `"web"` without `ref`, and `"computed"` without a `ref` naming the inputs.
2. Python post-check: collect numeric tokens (digits with optional `%`, currency, unit, decimal or thousands separators) from each slide's text frames and chart data, excluding page numbers and the speaker notes. A token not found in that page's `facts[].value`, `claim` or `evidence` is reported as `unplanned number "37%" on slide 4`. Advisory issue, same channel as overlap findings.
3. A page with any `illustrative` fact must show a visible localised label (示意数据 / Illustrative data / 参考データ); the lint checks the label text is present.
4. Skill sentence replacing the current "no invented numbers": a number or capability not in `facts` is removed or moved to an `illustrative` fact with its label; never restated as the user's.

Limit: only numeric tokens can be checked mechanically. Invented non-numeric features remain a skill rule and a review question.

### F. Image failure and reuse (small)

From Presenton: a failed planned `generate_image` result carries `retryable: boolean` beside the existing fallback instruction, so the model does not retry a non-retryable refusal; the existing lint "planned image unavailable; … fallback used" stays. Reuse keyed by (prompt, target size) maps to: when a new turn freezes a plan whose asset has the same `purpose`, `aspect`, `placement`, `textZone` and style, the host may offer the earlier bytes instead of a new paid attempt. Not verified against current host behaviour — `presentation.rs` L302–308 carries spend, and whether assets survive a re-freeze was not traced.

## 3. Not reusable, not found, or licence-limited

- **PPTAgent has no bounded-retry rule at this commit.** No retry count, round limit or attempt cap exists in `SKILL.md`, the references, `pptagent.py`, `core.py`, `visual.py` or `config.example.yaml` (only timeouts). Its control is "review must be current", not "at most N rounds". The bounded-iteration idea in §2 D comes from PPT Master's rubric (default one iteration, rollback on a new hard hit) and Ofox's existing two-preview limit.
- **PPTAgent has no image planning.** The skill only requires render dependencies to be local; nothing about image purpose, size or text-safe regions.
- **PPT Master's fact provenance is prompt-only**; no script enforces fact IDs. Its visual review is opt-in, needs Playwright/Chromium and Claude-Code team primitives, and its renderer applies no rule. Only the rubric's ideas transfer.
- **PPT Master's text-safe region is prose, not geometry.** There is no machine-readable safe-area rectangle or pixel check that a bitmap's quiet zone is actually quiet; quiet zones are written into the reference text and the prompt. The `textZone` enum in §2 A is an Ofox design, not an upstream format.
- **PPT Master's geometry is SVG-specific** (`preserveAspectRatio`, clip paths, nested crop viewports, illustration sheets with slicing, registered cut-out layers). The checker code operates on SVG and design-spec Markdown tables and cannot be lifted into the python-pptx path. Illustration sheets and cut-out derivatives would also exceed the four-image budget model.
- **Presenton's slot sizing depends on its template tree** (layout JSON with typed image elements and a hydrator). Ofox has no such tree before the Python code runs, which is why §2 A asks the plan to declare `aspect` instead. Presenton has no text-safe region, no crop policy, no review loop, and its warnings never return to the model.
- **Presenton's "factual accuracy" lines** (`generate_presentation_outlines.py` L143, L161–164, seen by search only) are general instructions with no check.
- **Licences.** MIT (PPT Master, PPTAgent) and Apache-2.0 (Presenton) all permit copying with notices; PPT Master's README footer adds "MIT licensed — attribution required". This proposal copies no code and no rule text, so no notice is triggered; if a later change ports code (e.g. the nearest-ratio helper), keep the upstream copyright line, and for Apache-2.0 also state changes. Do not copy from: PyMuPDF-dependent paths (AGPL), bundled icon/sound/font assets (separate terms, unreviewed).
- **Unverified.** Third-party notice files and template fonts were located but not read. Presenton line ranges in `presentation.py` L2339–2467 were confirmed by search hits, not read end to end.
