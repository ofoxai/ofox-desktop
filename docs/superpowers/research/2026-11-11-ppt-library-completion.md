## 2. 原生适配引擎

`assistant-runtime/src/python/deck.py` 新增数据驱动的构图层（`theme.decor.layout`，composition `spec`）：

- 每套风格自带命名画布（深色、浅色、饱和色），按页型或页码切换；卡片、文字、图表、页脚跟随当前页画布取色。
- 封面、章节、主张、内容、结束页各有标题位置、字阶、装饰形状（矩形、圆角、圆、旋转、重复），标题保持为版式自带的原生标题占位符。
- 卡片、指标、步骤各有风格化语言：开放线条、粗框硬投影、调色板色块、裸数字、编号步骤。
- 新增页面与构件：`statement_slide`、`closing_slide`、原生 `table`、`pyramid`、`code`。

每套风格是一份适配记录 `resources/adapters/<id>.json`（主题、配方、路由、三语名称与介绍、逐页映射），由 `scripts/presentation-adapters.mjs` 校验并合并进唯一的 `catalog.json`。原有五套保留手写构图，只补了逐页映射。Node deck 渲染器对新风格使用基础画布上的开放式构图（自带颜色、字体、字阶），不绘制多画布、装饰和色块语言；Python 引擎目前仅 macOS，可见 [已知限制](../../known-limitations.md)。

`scripts/render-presentation-adaptations.mjs` 按每套的逐页映射，用同一份自编内容（虚构的社区读书会，数值均标注为示例）生成原生 PPTX 并逐页出图，作为“原生适配”的证据，与“上游原稿”分开展示。

### 真实运行方式

沿用上一轮的受控 Host 驱动 `ppt_live_acceptance::one_guarded_case`（真实 AssistantHost、运行时、Python/OfficeCLI 引擎），扩展为接受本轮用例、两种模型和有界费用策略；Host 只看到本地转发器的一次性令牌。转发器只放行这两个模型的对话与生图接口，每次请求前按上界在单例与全轮上限内预留，结束后按上游返回的用量结算。读取 Desktop 账户钥匙串时 macOS 弹出访问确认、无人点击而超时，经用户选择改用 hal-vault 测试密钥 `2sey6k`，仅经命令替换注入转发器，未打印、未落盘。运行时只接受 `http://localhost:<端口>` 的本地网关，驱动为此改用 localhost。

## 11. 自适应配图与代码画图修复（2026-11-12）

用户在已安装 app（签名构建 `c76c019e`）里两次实测“做一个transformer介绍PPT”：一次手选 Daisy Days、配图“插图 最多 4 张/US$1”，一次 Auto、配图关闭。两份成品都没有生成图，也没有任何 `figure()`/`plot()` 代码画图；11-09 同题旧稿 13 页里有 6 页是代码画的结构图、注意力权重条形图和位置编码曲线。

**根因**（会话日志 `~/.ofox-desktop/assistant/<owner>/406d2b11…`、`8545664a…` 与代码核对）：

1. 配图设置只在 Host 内部。模型规划页面时看不到，思考原文是“host message doesn't mention image budget… I won't generate images”。冻结计划后才拿到 `visualBudget`，此时计划已是零图，返回 `no-generated-image-available`。11-11 的产品实测之所以生成了图，是因为验收提示词里手写了“新图最多 3 张、预算…”，这一验收方式掩盖了问题。
2. 代码画图被规划层挤掉：
   - 计划的视觉类型只有 none / native-chart / native-diagram / native-math / user-image / generated-image；
   - `nativeEditing.diagrams` 被模型默认置 true，描述写的是“使用即须原生可编辑”；
   - 技能文档把 `figure()`/`plot()` 写成“栅格化 PNG，需要时用原生对象”；
   - 偏离检查只认原生图形助手。
3. 新风格下代码图本身也有缺陷：
   - `plot()` 固定白底，在暖纸、粉彩、深色页上是一块白方块；
   - SVG 不写 `font-family` 时，中文在 @napi-rs/canvas 里画成方框，因为该渲染器没有逐字回退。

**修复**（先写失败测试再实现）：

- **Host 提前告知配图设置**：在 PPT 回合的开场说明里写明配图设置，`presentation_image_setting`。
  - 开启时：最多 N 张，至少 1 张，配在最需要的页面；
  - 关闭时：不生成图片，用代码画图或原生对象；
  - 没有 Python 时（Windows 或探测失败）不提 `code-figure`；
  - 不选风格、只引用已有 PPTX 改页面时也会告知。
  - `VisualPolicy::allows_images` 判断设置是否真的允许生图。
- **新增视觉类型 `code-figure`**（Rust 与运行时一致，仅 Python 路线）：
  - `figure()`/`plot()` 在出稿回执里记为 `fg`/`pl`；
  - 偏离检查认可它们，正文页的页型检查也接受代码画图；
  - `editing` 描述改为：代码画图属于示意，不因 diagrams=true 被禁，除非用户要求所有图示可编辑；
  - 技能文档恢复 `figure()`/`plot()` 的用途说明，正文上限 26500 → 27000。
- **`plot()` 跟随页面底色**：只把仍是 matplotlib 默认值的部分（白底、黑色边框和刻度、标题、轴标签、图例）换成页面颜色；数据区内的文字（如热力图格内数字）保持原色。navy 无主题色时按亮度取深色或浅色。
- **SVG 字体兜底**：根 `<svg>` 未写字体时，补上中文字体列表（与预览所用列表相同）。
- **独立审查**：报告 6 项，均已修复并加测试——navy 下 `plot()` 崩溃、深色页图例白框、热力图格内数字被改色、代码画图页被误报页型偏离、无 Python 时提示不可用类型、改页面时缺配图设置。另有 2 项低于阈值的建议也已处理：字体判断只看根标签、可编辑要求的措辞。

### 发现并修复

- **代码画的图里中文变方框**：SVG 指定了西文字体（`Georgia, SimSun, serif`）时，渲染器整段文字只用列表里第一个已安装的字体，不逐字回退；Georgia 没有中文。现在图里含中日韩文字时，每个字体列表前补一个同类的中文字体（衬线补宋体、无衬线补苹方），纯西文的图不变。测试：`python-deck-selection.test.mjs`“a figure whose SVG names no font…”。真实重跑时模型没有再用代码画图，所以只有测试覆盖。

### 随后修复：architectural-plan 的内容压进侧栏标题

- 原因：这套风格左右交替的浅蓝侧栏里放页码、标题和副标题。模型多页用写死的通栏坐标排版，没有按 `slide_regions` 给的可用区；检查程序只在盖住标题文字时报一条警告，第 3 页卡片压住侧栏标题时连警告都没有，而且警告不拦交付。
- 修复：
  - 新校验 `_validate_panel_regions`：在有侧栏的内容页上，模型画的内容跨过侧栏边线或压到侧栏标题区，直接报错（不是警告），每页一行列出出问题的内容和该页主区、侧栏可用区的坐标；引擎自己画的侧栏、标题、页码、整页背景不算。测试 `python-deck-native-compositions.test.mjs`“architectural content over the side panel is refused…”。
  - 风格说明（`catalog.json` 的 components）补一句：正文用 `slide_regions(s)` 放在主区或侧栏标题下方，越界会被拒绝。
- 真实重跑（`live/2026-11-13T1247/`，US$0.164622，账本余额 US$1.871793）：14 页全部按分区排版，交付时自动检查 0 条问题。模型一开始就按分区排，没有触发拒绝，所以拒绝这条路只有测试覆盖；案例集与 README 封面已换成这一份。
