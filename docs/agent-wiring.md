# Agent wiring

This describes the implementation in this repository. External agents may change their own precedence and schemas; validate the installed version before changing it. Paths below use `~` as the user's home, not a developer-specific path. Shared policies are in [AGENTS](../AGENTS.md); unresolved limits are listed [separately](known-limitations.md).

## Resolution, selection and restoration

[agent_env](../src-tauri/src/agent_env.rs) resolves Codex/Claude directories in order: explicit application override, process environment, cached/refreshed login-shell environment, platform default. `CODEX_HOME` defaults to `~/.codex`; `CLAUDE_CONFIG_DIR` defaults to `~/.claude`. Claude MCP is normally `~/.claude.json`, but moves inside an explicit `CLAUDE_CONFIG_DIR`. The snapshot is seeded from last successful discovery and refreshed in the background; first discovery may wait. Hermes uses application override, `HERMES_HOME`, then `~/.hermes` on Unix or `%LOCALAPPDATA%/hermes` on Windows. Pi/dsh accept absolute or `~/` overrides through `PI_CODING_AGENT_DIR` / `DSH_HOME`.

The UI distinguishes managed defaults from observed selection. Explicit CLI flags, project overlays and resumed sessions can select a different model; writing a default does not rewrite all running sessions. [live_model](../src-tauri/src/services/ofox_bind/live_model.rs) adopts recognized live selections without restoring stale templates. Claude/Gemini remembered concrete models align their managed environment defaults. [model_state](../src-tauri/src/services/ofox_bind/model_state.rs) uses revisions to reject stale saves. Profiles store model selections, not account keys or URLs; Codex/ChatGPT share one write target.

Binding records retain the pre-bind value and last written value. Unbind restores/removes OFox-owned route fields and unchanged managed fields, keeps recognized user changes and reports them. An absent field with a pre-bind value may be refilled. User effort, unrelated providers, hooks, MCP and sessions are preserved. [ownership](../src-tauri/src/services/ofox_bind/ownership.rs) is the rule source; do not promise every arbitrary edit can be inferred. `rewrite_bound_config` is a test helper, not a production call site. Production writes are binding, model-save, key-refresh and managed endpoint reconciliation.

## Resource ownership and native readers

The [library workbench](library-workbench.md) adds selective native discovery and physical-file batch coordination. Imports remain drafts, explicit checks remain separate from application, and batch recovery verifies completed writes without replaying unfinished groups.

Shared instructions, MCP definitions and immutable Skills drafts use versioned `library_*` settings without changing schema v11. Desired targets, verified receipts and prepared operations are separate. Saving/importing definitions does not apply them. Native projection requires a revisioned preview; apply and recovery recheck routing and file fingerprints under the same IO barrier used by model writes. Recovery only verifies completed writes. Restores keep this machine's proof, increase its epoch and do not resume old writes.

Instructions preserve bytes outside the OFox markers. MCP patches owned leaves in each native JSON/JSONC, TOML or YAML format; same-name foreign entries and edited owned values block writes. Field references support keep/set/clear without returning private values. Skills use append-only hash artifacts with a portable execution manifest; links and verified copies are staged beside targets and old material is retained until the new result and receipt are verified. Legacy enabled flags do not prove ownership.

Gemini respects an explicit app override, otherwise `GEMINI_CLI_HOME` plus `.gemini`; OpenCode uses its explicit app override or `XDG_CONFIG_HOME/opencode`. MCP auditing also includes OpenCode's three global files, `OPENCODE_CONFIG`, home `.opencode`, `OPENCODE_CONFIG_DIR` and inline content. Skills disclose shared and recursive readers, including Gemini/Codex `.agents`, OpenCode extra directories and Hermes configured paths. Dynamic routing keys and unresolved path references require a supported adapter and cannot be treated as literal paths. CLI/project overlays remain outside this global scope.

New WebDAV snapshots contain only referenced immutable skill objects and the same captured DB snapshot. A distinct archive name/encoding makes old clients refuse before applying. Old flat archives restore available content into drafts, leaving legacy/native roots intact; they cannot recover hidden files or execution intent omitted by the old exporter. Full application SQL/WebDAV backups still include private legacy definitions and are not shareable resource packages.

Source contracts were checked against [OpenCode v1.19.0](https://github.com/anomalyco/opencode/blob/v1.19.0/packages/opencode/src/config/config.ts) and [Hermes v0.22.0](https://github.com/NousResearch/hermes-agent/blob/v0.22.0/agent/skill_utils.py). Native execution, especially Windows, remains a separate acceptance gate.

## Installation, update and removal

[Installer](../src-tauri/src/commands/install_tool.rs) advertises host capabilities. macOS automatic CLI installation supports Apple Silicon via the bundled script; Windows uses [windows_install](../src-tauri/src/commands/windows_install.rs). Linux/Intel Mac support is not implied. Package mappings: Claude `@anthropic-ai/claude-code`, Codex `@openai/codex`, Gemini `@google/gemini-cli`, OpenCode `opencode-ai`, OpenClaw `openclaw`, Pi `@earendil-works/pi-coding-agent`, dsh `@deepseek-ai/dsh`; Hermes uses its installer. ChatGPT uses a native DMG path on macOS and Microsoft Store/winget fallback on Windows. WorkBuddy has no automatic installer here.

[tool_update](../src-tauri/src/commands/tool_update.rs) discovers the owning manager and executable instead of assuming npm: Homebrew, npm/pnpm/bun, native/vendor and desktop paths vary by tool. Hermes uses its updater where supported; unsupported sources provide reasons/manual actions. Node requirements are checked before install/update.

[uninstall_tool](../src-tauri/src/commands/uninstall_tool.rs) previews first and executes the verified owning manager. Homebrew autoremove is disabled; an unrelated formula named `dsh` is never treated as the agent. Managed native files are narrowly scoped; desktop apps move to Trash where supported. Hermes automatic keep-data uninstall requires advertised compatible flags; otherwise it is manual. Unknown sources stay manual. Config, sessions and shared runtimes/data remain. Frontend passes latest `stillBound` both times, subscribes before execute and filters by `operationId`; backend results determine remaining binding/key/install state. Partial results keep failed steps and a fresh copyable remaining command visible.

No destructive real-agent validation is required to test removal: use sandbox fixtures. External version behavior and native Windows acceptance are recorded as verified only when actually run.

Explicit [MCP connection checks](mcp-connection-checks.md) use frozen library definitions without applying them. Checks are local/HTTP fixture-tested, with native vendor versions and Windows process cleanup pending. Credentials and OAuth remain in their declared environment/native authorization flows.

The optional catalog has a separate Copilot CLI lifecycle on macOS arm64, using an existing compatible Node/npm and a dedicated OFox prefix without changing PATH or model bindings. External copies remain with their original manager. A frozen preview precedes mutation, and process ownership outlives a closed IPC waiter. Unknown or changed private state requires review. Installation does not add Copilot resource write adapters; the library only discloses its known potential shared `~/.agents/skills` reader. See the [acceptance boundaries](known-limitations.md).

Unbound core CLIs and Goose also expose [copyable manual installation commands](install-catalog-commands.md), with shell and PowerShell recipes selected by host. Unknown hosts and download-only applications show explicit guide text. Copying does not execute an installer or alter binding state; the manual recipes do not extend automatic lifecycle support.

Second-round library discovery adds ticket-scoped source inspection/reveal and metadata-only MCP comparison. Both positive and negative source proofs, definition revisions, routing and restore epoch fence those operations. Builtin recipe matches verify MCP definitions, instruction content or a skill's fixed provenance and artifact; they do not grant ownership. See [the workbench contract](library-workbench.md#第二轮添加定位与来源证据) for parsing, assignment and compatibility boundaries.
