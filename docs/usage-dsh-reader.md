# dsh usage reader

The native reference is the installed `@deepseek-ai/dsh` **0.1.2-rc.1**. The evidence is a synthetic native `Session` / JSONL persistence roundtrip, including concatenated zstd frames, plus a read-only review of that version's installed persistence, session, token conversion and compaction code. No AI request, live profile or real session content was used. This evidence validates the v0 event layout on macOS. dsh **0.2.1-rc.2** writes session format 4 (`session.v4.jsonl.zstd`) with the same row grammar; two real 0.2 sessions run through Ofox (one with a cache hit) parse to the provider-reported buckets, so format 4 uses the same rules. Windows and other native schema versions remain unverified.

The reader resolves the existing `DSH_HOME` home and enumerates every recognized physical `session.jsonl`, `session.vN.jsonl` and `.zstd` counterpart under the native sessions directory. Metadata display still chooses its active generation independently. Native 0.1.2-rc.1 writes `session.jsonl` / `.jsonl.zstd`; numbered generations are Ofox's existing compatibility convention, exercised with synthetic v0-layout files. A higher filename with an unsupported header schema cannot authorize a revision.

## Native facts and seed ownership

Only `assistant/message` records with `data.message.role=assistant` and `data.message.source.kind=model` become paid assistant facts. Identity is the native SID plus the native message ID in a separate assistant namespace. Moving a file, changing compression, or introducing a higher generation does not change request identity. No ordinal or filename becomes an acknowledged native identity. A recorded served `responseModel` takes precedence over the event's recorded source model; the current route, provider configuration and API key are never used to reconstruct a historical bill.

The four buckets are native `inputTokens`, `outputTokens`, `cacheReadTokens` and `cacheWriteTokens`. dsh input is already the fresh-input bucket, and output already includes reasoning; neither cache subtraction nor extra reasoning addition is applied. Missing optional cache buckets mean zero; explicit zero remains a real native record. Invalid integers fail the scan. Compatible ledger cost zero is a placeholder rather than a tool bill. Current OFox estimates use the shared four-bucket `PriceCatalog`, including scientific decimal rates, and do not alter saved cost. Additional billing units remain outside this estimate.

The v0 header's `seedLength` is the inherited event cut. Copied parent events before it do not become new child spending. The constructor accepts an inherited final `session/end-seed` at `cut - 1` or adds one at `cut`. Markers may recur on later resumes, so the last marker cannot replace that durable cut. A parent reference alone does not prove that a session was seeded. A declared seeded session without a known cut is partial and its copied region is excluded. A missing seed boundary marker or missing parent source is reported separately. Native parent and child SIDs remain separate ledger identities.

Native v0 commits only LF-terminated rows: even syntactically valid JSON at EOF without LF is an incomplete tail. Known packed text, reasoning and tool-call deltas expand the sequence cursor but do not create extra spending. Compaction usage is currently `unsupportedUsageEvent`; replacement summary messages do not become another assistant call. Thus this slice does not claim complete dsh spending when a compaction or other unsupported usage event exists.

## Revisions, ordering and transactions

The bounded scan reads the complete changed roster outside the database lock, using the same open handle for zstd decoding and physical identity checks. Same-generation conflicting replicas fail rather than selecting a winner by mtime. Supported higher generations may replace a live native event; old-only events are retained because active context is not total spending.

Provider-local `nativeGenerations` evidence stores hashes of native SIDs and event identities, with the highest trusted SID generation and each event's generation. This prevents rollback when the highest file disappears or its new projection omits an event still visible in an old file. A SHA-256 `contentHash` detects accidental loss or changes to the version-1 SID/generation/event-generation projection; unrelated unknown fields are preserved and excluded from that projection. It is an integrity check, not authentication or negative acknowledgement evidence. The extension shares the provider manifest's CAS; commit also verifies the ledger epoch captured during prepare. Restore can preserve this positive ordering evidence while revoking historical negative acknowledgement trust. Facts, ordering evidence, receipts and checkpoints commit in one transaction. Ordering is written before receipts capture the final provider generation. Missing or damaged generation evidence with prior history preserves existing facts and reports partial coverage; it is not initialized as generation zero. Future extension versions and unrelated manifest fields are preserved. With prior dsh history, a lost, corrupt or unsupported ordering lease continues to block native ledger updates; ordinary rescans do not reconstruct it or silently regain completeness. An explicit, separately reviewed CAS recovery path is still needed.

No source bodies, prompts, replies, tool arguments, provider credentials or raw errors are stored in usage facts or proof. A missing native epoch-millisecond timestamp is partial and cannot fall back to mtime, header creation time or the current time. Normalized facts retain native milliseconds; the existing schema-11 live ledger still stores whole seconds, so the new query path cannot claim subsecond precision for these persisted rows.

The limits are 10,000 physical sources, 64 MiB per encoded or decoded source, 128 MiB per roster and 100,000 parsed facts. Generation evidence allows 20,000 SID hashes and 100,000 event hashes within the existing 4 MiB provider-manifest ceiling. Exceeding a limit fails the batch and preserves prior state; history is never evicted to manufacture negative evidence. An unchanged roster skips body reads. File, decoding, checkpoint and transaction failures preserve the last successful ledger/proof/checkpoints. Typed partial coverage does not block unrelated source maintenance.

## Capability limits

The original reader-only slice provided native dsh facts to the usage overview and requests without enabling session/project analysis. The current [native analysis bridge](native-analysis-bridges.md) also projects native session identity, recorded project metadata and proven own usage from the complete verified roster. It reuses durable generation ordering, seed boundaries and acknowledged event evidence; verified delegated parent relationships must pass lineage validation rather than being guessed. Native child SIDs remain separate ledger identities, and a session-list amount uses only that session's own facts, not a parent's combined total.

Message counts and activity remain unavailable because this bridge has no verified effective-message projection; usage events are not conversation messages. Other header versions, paid compaction events and archived aggregate revision repair still require separate evidence and regressions. Reader fixtures and synthetic analysis benchmarks do not establish actual agent execution, final-source release performance or Windows acceptance.
