# 用量项目归属与共享筛选

项目筛选使用与会话分析相同的原生目录哈希。概览、请求列表、摘要和 CSV 在同一条件下查询；切换子页保留项目条件，重置同时清除。旧后端未声明共享项目能力时，保留会话分析单独筛选并解释切页时清除条件。

## 数据规则

- 读取现有用量账本时，在同一 SQLite 事务读取机器本地会话缓存和当前价格目录。查询不打开原生正文、不新增账本记录，也不更改 schema v11。
- 只有 OFox 导入的工具／保留 provider／来源三元组，才能用原生 SID 关联缓存。代理记录即使有相同 SID，也不猜作该项目。
- 已验证的子会话归属根会话及根项目。缺父、成环或冲突 metadata 返回未解析；不能改归为“未知项目”。后者只表示已解析、但原生没有记录目录。
- 旧日汇总没有项目维度。无项目筛选时保留在总量；筛选时排除并返回 `legacyProjectUnavailable` 与被排除的汇总行数，不按首末时间或现有项目平均分配。
- 请求快照冻结项目成员、价格与条件。原生 metadata 后续修改不改变已打开分页、详情和 CSV；新查询使用新的归属及快照版本。
- 概览增加“已识别会话数”“已识别项目数”和项目排行。无法关联会话的采集记录保留在总量并单独提示；这些计数不是缺失历史的完整会话／项目总数，`attribution.partial` 明确说明限制。未知目录分组不算已识别项目。

## 阶段验证

7 项真实 RED 后实现，9 项项目回归通过，覆盖 Claude、Codex、Gemini、OpenCode，未知／未解析／代理同 SID、历史汇总、冻结成员、根会话与缺父。查询数据 6 项、概览 2 项、请求 4 项和会话分析 59 项兄弟测试通过，Rust fmt／diff 检查通过，独立评审无剩余确定 P1／P2。

前端先取得 2 项真实 RED；修复后 typecheck、format 与全量 121 文件／852 项单测通过。以上是此切片的工作区结果，不能替代最终集成门禁、真实数据对账、原生窗口和 Windows 验收。新来源按实际桥接能力开放，未接桥的来源仍保留未解析说明。
