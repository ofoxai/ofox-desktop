- 六格 KPI、紧凑排行、工具维度、按时段／日历、三种 Top、分布和可解释的数据状态。

## 回归与评审过程

先取得失败证据再实现：已知活动子集与完整 cohort 活跃榜、原生归档发现、同时间 SQLite 原生顺序、阅读与搜索、双向导航、排行请求的标准化与快照身份、刷新时热力图焦点、零活动分布边界。

独立 Bugbot 确认4项 P2：排行弹窗缺少鼠标关闭与焦点恢复；Pi完整记录构建在受限上下文前预读；压缩输入与声明窗口缺少边界；SQLite打开连接后捕获文件证明存在替换间隙。后续复审另确认候选校验与真实open之间的替换窗口，以及阅读器自动准备继续命令仍可能走旧Pi预读；两项同样先RED再修。最终静态复审未发现剩余P1/P2，运行验证由主线执行。原生读取预算只覆盖搜索和新阅读器，不能推广到旧消息API或所有导出路径。额外独立分析评审补齐真实 query 入口的23／25小时DST对账测试，没有将新增覆盖冒称已修复的历史错误。

## 可复现性能入口

前端使用[独立生产renderer基准](../scripts/session-workbench-benchmark.md)，10k无正文会话、100项目、16模型、1460日桶，每页热身3次后30次。缓存替换→React提交／双rAF单独计时，不包括扫描、IPC或fixture生成。首轮与Rust全量验证并行：用量p95 270.2ms、会话p95 239.3ms；会话单轮最大536ms，保留原始样本，不把p95通过冒充每次都低于500ms。空闲复测用量p95 250.7ms、会话p95 225.3ms，最大会话单轮504.2ms。两页p95低于500ms，但单轮尾延迟仍会略超目标；原始两轮JSON均保留在交付包。
