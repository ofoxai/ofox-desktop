# Pi usage reader

The fixed reference is official `@earendil-works/pi-coding-agent` **0.84.4**, session schema **3**. Pi was unavailable on this machine's PATH. A temporary npm package installed with `--ignore-scripts` was checked using its pure `SessionManager` API on Node **24.19.0**, with temporary home, agent and session directories. The synthetic roundtrip exercised divergent branches, a fork, assistant usage, compaction, branch summaries and valid JSON at EOF. It made no AI request and read no live profile or session. This is temporary package verification on macOS; installed CLI behavior, Windows and other schema versions remain unverified. The primary contracts are the versioned [session manager](https://github.com/earendil-works/pi/blob/v0.84.4/packages/coding-agent/src/core/session-manager.ts) and [usage/message types](https://github.com/earendil-works/pi/blob/v0.84.4/packages/ai/src/types.ts).

## Events and ownership

Spending reads every native assistant entry in the file, including abandoned branches. The existing session display still follows the active branch. Native identity is the native SID plus the assistant entry ID. Entry IDs are collision-checked only inside one session; they are never treated as globally unique. A single file can move without changing its request identity. Conflicting physical replicas of one native identity fail rather than selecting a winner by mtime. A same-file revision replaces its live fact without rewriting saved cost.

The four native usage buckets are `input`, `output`, `cacheRead` and `cacheWrite`. Input is already fresh input; output already includes reasoning. Missing buckets remain unknown rather than becoming zero. Explicit four-bucket zero is a real native event. Invalid integers fail the batch. The recorded served `responseModel` takes precedence over the recorded requested model. Current routes, API keys, configuration and native cached prices are not used to reconstruct historical billing. Compatible saved cost zero is a placeholder; current OFox estimation uses the shared catalog and keeps unknown prices distinct from zero.

Forks have a new SID and an explicit `parentSession` path while retaining copied entry IDs, timestamps and messages. The roundtrip used the same millisecond for every parent, child and header timestamp, so a header-time threshold cannot identify copies. Sync resolves only parent paths present in the controlled source roster. It verifies the initial copied prefix against that parent's entries and native parent chain, accounting for removed label entries. Copied spending stays with its original source; only new child spending uses the child SID. The transient entry comparison is not persisted as body content or negative acknowledgement evidence.

An absent parent, an unverifiable prefix, an incomplete ancestor or a cycle makes the child partial and preserves previous facts. If a previously counted ancestor event disappears from an intermediate parent's current prefix, its trusted native SID-scoped acknowledgement prevents that copied event from becoming new child spending. The check follows only the resolved parent chain, bounded to 64 ancestors. This positive-history check also survives a parent move when the native `parentSession` path is explicitly repaired; it does not grant complete negative evidence. Moving the parent without updating the child's native `parentSession` path also leaves the child partial; this slice does not reconstruct that association from filenames, timestamps or an unrestricted filesystem search. A single-file normalized read cannot prove fork ownership and returns partial coverage without importing its copied spending. It must not be described as a complete moved-fork import.

Native compaction, branch-summary and tool-result usage lacks a reliable event-level model in the checked schema. These remain `unsupportedUsageEvent`, with partial coverage. The current model is not assigned to those calls. Native user, context, summary and tool-display entries do not become extra assistant calls.

## Discovery and transactions

Discovery uses the existing agent directory, its `sessions/<project>/*.jsonl`, and an absolute or home-relative custom directory selected by `PI_CODING_AGENT_SESSION_DIR` or global `settings.json` `sessionDir`. Environment selection takes precedence. Unknown or unreadable settings and an existing non-directory source are errors, never empty defaults. Settings and event sources are opened without waiting for a FIFO writer, checked as regular files through their open descriptors and read within byte bounds. Relative custom directories cannot be resolved without their original startup working directory and remain unsupported; roots containing unresolved `..` components are also rejected. CLI-only and project-local custom roots outside these observed directories are not discovered. Symlink source roots or entries are unsupported in this usage slice.

Pi accepts syntactically valid JSON at EOF without LF. The usage reader accepts it read-only and does not perform the native loader's newline repair. A torn EOF is partial and its checkpoint stops before that fragment. Malformed committed rows keep native tolerant parsing while marking enumeration partial; they cannot establish complete negative evidence.

The changed roster is parsed outside the database mutex. Before publishing, one transaction rechecks all source stamps, the complete roster, provider evidence and checkpoints. Facts, receipts and checkpoints then commit together; file, parse or transaction failures preserve the previous successful state. An unchanged roster skips body reads. Ordinary typed partial coverage does not block unrelated source maintenance. Multi-root freshness and transaction fences must include every observed custom root.

Bounds are 10,000 physical sources, 20,000 directories, 64 MiB per source, 128 MiB per scan and 100,000 parsed native entries, plus the shared proof budgets. Budget failures preserve previous state; history is not evicted to manufacture missing-event evidence. Usage facts and proof contain no prompts, responses, tool arguments, credentials or raw errors. Normalized facts retain native milliseconds; schema-11 live rows still store whole seconds. Repairing a revision already folded into historical aggregates remains unsupported.

Session analytics, project filtering and a fork-aware session-center usage bridge remain unsupported. This slice exposes the provable assistant facts to overview and request queries within the discovery and event limits above.
