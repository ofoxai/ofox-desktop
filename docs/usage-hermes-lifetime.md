# Hermes 累计用量

Hermes 的统计按原生累计计数展示，入口位于用量筛选行。它不参加日期、项目、每日趋势或请求筛选，也不生成虚构请求记录。`get_usage_source_summary({toolId: "hermes"})` 返回独立的 version 1、`scope: "lifetime"` 响应；`lifetimeUsageSupported` 不表示 `usageSupported` 或会话分析桥接已开放。

## 原生口径

实现依据 Hermes `0.21.7+18.g590af66`、SessionDB schema 31，并用该版本的原生 SQLite API 在临时环境生成合成统计。只读统计列，不读取正文，也不使用当前路由猜测旧记录的模型。

- 主 Tokens 为新输入加输出；缓存读取、缓存写入和累计 API 调用数单列。累计调用数不是可归属的 HTTP 请求列表。
- 主请求与 voice 共用累计池；模型行是池的分解，不能再加到累计池上。已知辅助任务单独追加，未知任务只保留可证明的下界。
- 缺失计数保持未知，明确零值保留为零；无法完整归属的模型显示未归属。模型分解与池不一致时拒绝该分解，保留池及明确限制。
- 计数覆盖、模型归属覆盖与价格覆盖分别返回。历史 schema 的模型归属无法凭现有总数补全。原生费用零值不能证明免费；界面使用当前 OFox 目录的四桶估算，并标明缺价与额外单位限制。

## 读取与缓存

设置健康检查与目录解析在同一个短 `config_io` 锁内执行。设置不可读时返回静态错误，不回退到默认目录；真实文件读取在锁外进行。

原始 `state.db` 与可选 WAL 仅以只读文件句柄打开。实现校验文件身份、大小、修改时间、变更时间及 WAL 集合，复制到临时目录后再用 SQLite 事务查询，避免在用户原目录创建 SHM。前后变化、非普通文件、回滚 journal、损坏或不支持的 schema 均返回明确失败。主库、WAL 或 journal 的叶路径为符号链接时明确失败并保留旧快照；SQLite 会解析目标主库并使用目标 WAL，按别名复制 sidecar 无法证明快照完整，因此不读取可能过时的别名副本。主库与 WAL 合计上限为 512 MiB，`sessions` 与 `session_model_usage` 每张统计表分别最多 200,000 行，标签长度上限 1,024 字节。

最后一次稳定快照保存在机器本地共享来源缓存的独立 Lifetime 分区。CAS 防止迟到读取覆盖较新结果，并保留缓存信封与其它分区的未知扩展字段。源缺失或失败时保留旧快照，标明陈旧与错误；同一文件版本命中缓存时只重新估价，不重解析或推进成功时间。响应 `lastSuccessAtMs` 表示最后一次稳定原生读取，不代表所有统计覆盖完整，也不能代替公共来源健康中的完整可信成功时间。

## 界面与验证边界

只有用量页可见、用户已绑定且后端声明累计能力的 Hermes 显示入口。打开或主动刷新才请求累计数据。关闭、解绑、页面隐藏及地区切换使迟到请求失效；响应地区必须匹配请求时选定的 apex。模型每次展开 50 行，Escape 关闭后焦点回到入口。中英日文案覆盖主 Tokens、累计范围、缺价、未归属与陈旧状态。

后端 23 项专项、前端／API 26 项专项，以及设置不可读／恢复与页面挂载回归已通过独立阶段验证。900px 浅／深色开发预览已检查弹窗溢出、分页展开、Escape 和焦点回退。预览采用合成响应，原生 API 证据也来自沙箱持久化；它们不表示真实账户费用或 Windows 已完成验收。最终全项目门禁与原生窗口验收另记在[实施记录](implementation-progress-2026-10-15.md)。
