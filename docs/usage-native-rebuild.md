# 本机用量重建与统计口径

本轮从 `67cbfba5` 继续，参考固定的 Magpie `bfaedf18301d02a423bd5422d22e41432d231ab8`，将统计规则移植到现有 Rust 服务。应用不运行 Magpie，不增加第二套日常统计开关，数据库 schema 保持 v11。参考实现的 MIT 许可随源码及应用资源保留。

## 一份投影供四处读取

Codex 原生解析器 `codex_native.rs` 输出无正文的事件、原生线程身份、计费会话身份、父线程、来源指纹及覆盖原因。概览、有效明细、会话分析和会话列表金额共用已接受的投影。原生线程与共享计费会话不是同一个身份；子线程只展示可证明属于自己的消耗。

新解析覆盖旧 `token_count`、`token_usage_record`、压缩内嵌用量、分页、运行计数重置和迟到计数修订。优先使用原生响应 ID；没有响应 ID 时，需要原生运行边界和可核验计数区间。相同 Tokens、文件修改时间或相同目录名称不构成去重／归属证据。复制的后续 `session_meta` 不覆盖第一个正式头部；继承历史没有可靠边界时只保留能证明的部分。

活跃、归档、zstd 压缩、同线程续段和副本共同核验。冲突隔离到相关事件或来源；有效兄弟事件继续参与统计。列表的已知金额可保留，但统计覆盖不完整时必须标为部分估算。

## 活跃、消息与分位数

“工具活跃时长”使用同一主来源的日志事件顺序：只累加相对已见递增时间戳的正间隔，且间隔严格小于五分钟。对话和运行事件均可贡献时间；消息数仍只数有效用户／助手消息。子来源不会重复增加父会话活动。

完整间隔归入后一个事件所在日期及小时，包括跨午夜、跨小时和夏令时转换；不均分每日时长，也不裁成窗口边界附近的虚构活动。内部保留毫秒。并发会话可以相加，它不是人的工作时长。中位数和 p90 采用 nearest-rank。纯元数据文件不创建活动会话。

九种分析桥接都保留各自的原生身份、分支及读取优先级。Claude、Codex、OpenCode、WorkBuddy、Pi 有可验证的运行事件投影；没有可靠原生时间投影的来源保持未知。Gemini、dsh、OpenClaw 不因有 Tokens 就获得活跃时长；Hermes 按 magpie 规则从 `started_at` 起按消息顺序计算活跃时长。模型筛选不能可靠分配工具活动时，活动指标仍不可用。

## 历史与金额保护

接受新一代 Codex 投影后，有效统计替换旧 `app_type=codex / data_source=codex_session` 导入明细和已证明的旧 Codex 汇总贡献；不把二者相加。实测请求和其他来源保留原有贡献。

旧账本记录、请求 ID、原始 Tokens 和五个已保存金额字段保留；Codex 旧导入行不再参与自动补价或明细清理。数据状态中可进入“原始历史记录”审计视图。无法唯一证明旧行对应哪个重建事件时，不建立猜测映射；原始历史不参与修复后的主统计。

新事件没有历史保存金额、HTTP 状态或耗时，就返回未知。不会从输出或 Tokens 推断成功。费用仍是当前区域的 Ofox 现价估算，与账户实际扣费不同；未知价格显示“—”，已知零保留零，部分价格／统计覆盖保留已知金额及“＋”。

主 Tokens 为新输入＋输出；缓存读取和写入另列。为对齐固定 Magpie 四桶规则，原生 input 中同时包含的 cache-read／cache-write 在新输入中扣除。Codex CLI 自身输入显示与此不必相同。缺少 cache-read 时不能证明新输入，相关调用不制造零值；缺少 cache-write 保留可证明的计数并标不完整，不能将其称为实测零。参考实现的字段别名和缺失值策略差异在[对账说明](../scripts/usage-parity/README.md)中单列。

## 发布、取消与恢复

重建在后台进行，支持本机进度查询和取消。解析过程中旧一代继续可读；新一代只在完整来源集合、各来源修订、路由及 ledger epoch 核验通过后，通过同一 CAS 事务发布。取消、来源变化或提交失败不发布半套来源。取消回执与最终事务提交串行，不能已提交又报告已取消。

恢复数据库导致 epoch 变化时，重新核验未变化的来源并发布当前 epoch 的 warm 回执，不必重新解码正文。已接受来源消失或读取失败时保留已知事实并显示问题；来源重新可读后恢复定位和当前收据。旧解析版本不能冒充已重建结果。

查询响应兼容增加方法版本、输入快照标识和来源覆盖。来源数与消息／活跃／分位数样本分别报告。无有效用量证据时界面不显示虚构零值。旧后端能力缺失时保留旧统计说明。冻结分页继续使用已有十分钟有效期；新查询不混用代际，刷新使旧金额／排行／定位证据失效。

## 预算与验收边界

Codex 流式读取使用 64 KiB 缓冲、32 MiB 单行上限、2 GiB 单来源解码硬上限和 8 MiB zstd 窗口。达到投影／协调预算时保留已证明部分和原因；仍在允许预算内核验完整指纹。硬读取失败保留上一代，不能冒充空文件。整体缓存、冻结排行和原有本机预算继续生效。

冻结样本与独立 Go 参考使用相同来源 SHA、UTC 范围及测试价格，逐项比较线程、四桶 Tokens、每日值、nearest-rank、活动毫秒和估价。参考字段不支持、缺失证据、筛选和生产价格差异分别记录；不以某张截图的总数作为目标。

合成界面、沙箱写入和 release 10k 查询只证明各自测量范围。macOS 安装复验、Windows 原生验收、公证以及真实资源消费必须分别记录。本轮不重启付费验收，不把替换安装称为跨版本线上更新验证。
