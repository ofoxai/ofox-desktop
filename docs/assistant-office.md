# Assistant Office attachments — 2026-10-28

Scope: Fizzy #1234, S4.

## Implementation and limits

The built-in Node 22 runtime reads DOCX body/table text, XLSX cells (sheet names,
logical order, sparse coordinates, shared/inline strings and cached formulas),
and PPTX slides plus notes in presentation order. It never executes macros,
calculates formulas, fetches external relationships or reads embedded images.
DOCX headers, footers, footnotes/endnotes and comments are explicitly excluded.
User and model receive that scope, the text-only warning, and a separate warning
when structure/order could not be verified. XLSX stored numbers are unformatted;
formula caches can be stale. Empty, encrypted, damaged and over-limit documents
have distinct localized explanations in Chinese, English and Japanese.

The reader inflates only selected XML parts. Its limits are 4,096 ZIP entries,
15 MiB selected XML total, 500:1 expansion per part above a 1 MiB allowance,
100 nested XML tags, 200,000 `<` markers per XML part, and 16 Mi UTF-16 output
characters. It validates streamed byte counts and CRC, rejects DTDs, unsafe or
duplicate paths, and does not follow external links. Parsing runs in a worker
with a 128 MiB old-generation heap and 10-second deadline; cancellation terminates
it. The worker receives no inherited environment or Node startup arguments.

Dependencies are pinned to `yauzl` 3.4.0 and `fast-xml-parser` 5.11.2; all ten new
locked packages declare MIT. License files ship with their packages. The
[Office notices](../assistant-runtime/notices/office.txt) additionally include
`@nodable/entities` 3.1.0's omitted license (from its published gitHead), and the
buffer-crc32/fd-slicer licenses for code vendored into yauzl. Packaging tests
check the complete dependency closure and the missing/vendored notices.

Primary sources: [yauzl](https://github.com/thejoshwolfe/yauzl),
[fast-xml-parser](https://github.com/NaturalIntelligence/fast-xml-parser),
[@nodable/entities license](https://github.com/nodable/val-parsers/blob/ac48e7ea591da372be023a481875c747535812b3/LICENSE).

## Legacy `.doc` assessment

`word-extractor` 1.0.4 is MIT; npm reports that version's latest metadata change
as 2022-06-29. Its current published parser correctly extracted a synthetic
Chinese `.doc` produced by macOS `textutil` (Chinese/Japanese/English, tabs and
numbers). It did not pass malformed-file robustness testing: changing the
19,456-byte fixture's directory FAT chain to a two-sector cycle exhausted a
child Node process's 32 MiB heap and terminated it with SIGABRT. The package's
`getSecIdChain` detects self-loops but not longer cycles. This test ran in a
bounded child process with a five-second timeout, never in the application or
against a user's document.

Decision: do not ship `word-extractor`; legacy `.doc` remains unsupported with
an explicit “save as docx or PDF” hint. This is a reliability decision, not a
claim that ordinary Chinese `.doc` text cannot be decoded. Source:
[word-extractor 1.0.4](https://www.npmjs.com/package/word-extractor/v/1.0.4),
[project](https://github.com/morungos/node-word-extractor).

## Verification

The first 19 runtime acceptance tests failed against the previous unsupported
implementation. The import and UI outcome tests also failed before their fixes.
Additional regressions cover Excel phonetic text and Word compatibility
alternatives; both reproduced the independent review findings before fixing them.

Fixtures `assistant-runtime/test/fixtures/office/chinese.{docx,xlsx,pptx}` are
synthetic files generated by python-docx, openpyxl and python-pptx; the adjacent
`generate.py` documents their provenance. Production and tests only read their
checked-in bytes and do not need Python. Runtime tests check Chinese/Japanese
text, tables, order, coordinates and notes. The Rust host integration imports
all three files into temporary configurations and captures the real bundled
Pi SDK's outgoing model request through local mock gateways. It tests both
initial apex choices, both switch directions, and a fresh host continuing the
same native history. Outcomes remain partial after reload; no synthetic Key is
persisted. This is local transport verification, not live gateway billing.

Native Windows execution and final application click acceptance remain part of
S5. See [S4 progress](assistant-s4-progress.md) for the other unfinished work.
